# 阶段十七：最终审查和验收

> 阶段任务书。阶段编号以 `docs/phases/README.md` 为准；规则、命令与红线见项目根 `AGENTS.md`。

阅读 AGENTS.md，执行项目最终验收阶段。

请以代码审查和发布验收的方式检查整个项目。

检查范围：

1. C++20 代码是否能够完整编译。
2. 是否存在裸 new/delete。
3. 是否存在明显的资源泄漏。
4. 文件句柄是否由 RAII 管理。
5. 线程是否能够安全退出。
6. 是否存在数据竞争风险。
7. 大文件是否全程流式处理。
8. 是否存在路径穿越风险。
9. 是否存在越权读取和越权写入。
10. 是否存在 SQL 注入风险。
11. 上传会话是否持久化。
12. 断点续传是否真正可恢复。
13. 重复分块是否幂等。
14. 完成上传是否重新计算 SHA-256。
15. 版本冲突是否返回 409。
16. 回收站恢复是否可用。
17. 分享 Token 是否安全。
18. Redis 不可用时系统行为是否明确。
19. PostgreSQL 不可用时系统行为是否明确。
20. 磁盘空间不足时系统行为是否明确。
21. 前端是否可以完成主要用户操作。
22. 前端是否正确处理 loading、error、retrying、offline 状态。
23. 页面刷新后上传是否可以恢复。
24. Docker Compose 是否可以启动。
25. CI 是否可以运行。
26. README 是否与实际代码一致。
27. API 文档是否与接口一致。
28. 测试是否覆盖正常流程和异常流程。
29. 是否存在未经说明的伪代码、空函数或 TODO。
30. 是否有未验证功能被错误描述为已完成。

请输出：

1. 按严重程度排序的问题：
   - Critical
   - High
   - Medium
   - Low
2. 每个问题包含：
   - 文件路径
   - 行号
   - 问题描述
   - 复现方式
   - 修复建议
3. 已通过的验收项。
4. 未通过的验收项。
5. 已执行的命令。
6. 测试结果。
7. 未验证事项。
8. 发布前必须修复的问题。
9. 可以延后到后续版本的问题。

约束：
- 不直接修改代码，除非发现的问题属于阻塞发布的明显缺陷。
- 不为了让测试通过而删除测试。
- 不降低安全检查。
- 不忽略用户已有修改。
- 不编造测试结果。
