# 测试与验收标准

## 测试分层与范围

| 层 | 范围 | 技术 | 位置 |
|---|---|---|---|
| 单元测试 | 后端纯逻辑：校验、状态机、哈希、权限、限流、队列 | GoogleTest | `backend/tests/unit/` |
| 存储测试 | 对象存储抽象与本地磁盘实现 | GoogleTest | `backend/tests/unit/` 或 `backend/tests/integration/` |
| 集成测试 | PostgreSQL、Redis、REST API 端到端 | GoogleTest + 真实依赖服务 | `backend/tests/integration/` |
| 前端测试 | 组件、页面、交互、响应式布局 | Vitest + Playwright | `frontend/tests/` |
| 故障与并发测试 | 人为制造依赖失效、并发冲突、异常输入 | 集成测试 + 脚本 | `backend/tests/integration/`、`scripts/` |
| 性能基准 | 吞吐量、延迟分位、内存、并发连接、失败率 | Google Benchmark | `backend/benchmarks/` |

依赖服务（PostgreSQL、Redis）用 Docker Compose 启动；测试必须使用固定、可复现的数据集。

故障测试和性能测试都必须能够以 PowerShell 脚本形式重复执行：

- 压测脚本失败时必须返回非零退出码，不得静默通过。
- 性能测试不能影响默认开发环境。
- 不伪造性能数据；如果无法在当前环境运行压力测试，必须明确写出「未验证」。

新增业务功能同步新增测试；不得为了让测试通过而删除或跳过测试。

## 六、Sanitizer 与性能基准

### Sanitizer 构建

必须建立以下三种构建：

- ThreadSanitizer 构建。
- AddressSanitizer 构建。
- UndefinedBehaviorSanitizer 构建。

对应的 CMakePresets 至少提供 `debug` / `release` / `asan` / `tsan`。

**本机实际可用的跑法**（2026-09-18 复验）：

```powershell
.\scripts\build.ps1 -Preset asan              # ASan 构建（独立 triplet x64-windows-asan）
.\scripts\test.ps1  -Preset asan              # ASan 全量（单元 + 集成）
.\scripts\test.ps1  -Preset asan -Label unit  # 只跑单元测试（不打库，快）
```

实测结果：ASan 构建通过，**单元 160/160 + 集成 133/133 全过，无 AddressSanitizer 报告**；
TSan / UBSan 因 MSVC 不提供、依赖又是 MSVC 静态库而**未验证**（见 README「已知限制」）。

> ⚠️ 集成测试**不要加 `-j`**：并行会抢同一个数据库并产生大批假失败（实测 80 个）。

### 性能基准

使用 Google Benchmark 测量以下指标：

| 指标 | 说明 |
|---|---|
| 上传吞吐量 | 单位时间完成的上传数据量 |
| 下载吞吐量 | 单位时间完成的下载数据量 |
| API P50 延迟 | 中位响应延迟 |
| API P95 延迟 | 95 分位响应延迟 |
| API P99 延迟 | 99 分位响应延迟 |
| 内存使用 | 峰值与常驻内存 |
| 并发连接数 | 可持续承载的并发连接 |
| 失败率 | 请求失败比例 |

### 结果归档

- 将测试方法和结果写入 `docs/performance.md`。
- 在 README 中说明测试环境和限制。
- 基准数据必须在 README 中注明测试环境。
- 性能指标不应脱离实际硬件直接声称；必须提供压测脚本和测试结果。
- 未能在当前环境运行的压测必须标注「未验证」。

## 八、局域网真机测试（Windows 电脑 + 安卓手机）

本项目是局域网文件服务，真实链路必须用**另一台设备**验证。准备：一台跑服务端的 Windows 电脑、
一台安卓手机（浏览器即可，不需要装 App）。

### 8.1 两种网络

| 场景 | 做法 | 注意 |
|---|---|---|
| **手机热点（建议先用这个）** | 手机开热点 → 电脑连这个热点 → 手机浏览器打开电脑的局域网地址 | 电脑会拿到 `192.168.43.x`（安卓热点网段）；手机就是网关，一定访问得到电脑 |
| 校园网 / 公共 WiFi | 手机与电脑连同一个 SSID | 很多校园网开了**客户端隔离**，设备之间互相访问不通 → 手机打不开电脑；换热点或用自己的路由器 |

### 8.2 步骤

1. 电脑双击桌面按钮 → 按 `1` 启动，记下输出里的 `📱 手机访问: http://<IP>:5173`
   （菜单按 `3` 也能看到这一行）。
2. 手机浏览器打开该地址（**必须是 `http://<IP>:5173`，不是 `localhost`**）。
3. 用管理员账号登录（还没有就按菜单 `5` 创建，见 README「快速开始 8」）。
4. 依次验证：上传一个 100 MiB 左右的文件 → 列表能看到 → 下载 → 断点续传（上传中途刷新页面再继续）
   → 新建文件夹 / 移动 / 重命名 → 删除进回收站 → 恢复 → 创建分享链接并用手机浏览器打开分享页。
5. 换另一种网络重复第 1～4 步（**IP 会变**，重新看菜单里的地址）。

### 8.3 排错

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 电脑自己也打不开 | 服务没起 / 端口不对 | 菜单按 `3` 看状态；确认前端监听 `0.0.0.0:5173`（`netstat -ano | findstr :5173`） |
| 电脑能开、手机打不开 | 防火墙拦入站，或网络做了设备隔离 | 本机实测 `node.exe` 与 `lan_file_hub_server.exe` 都有 **Public Profile 入站放行规则**；缺就用管理员 PowerShell 补规则，校园网则改用热点 |
| 昨天能用、今天不行 | 局域网 IP 变了 | 重新看菜单 `3` 里的「手机访问」地址 |
| 页面能开但接口报错 | 前端代理没连上后端 | 看 `%TEMP%\lfh-frontend.log` 与 `%TEMP%\lfh-backend.log` |

### 8.4 手机端预期（先说清楚，避免误判成缺陷）

界面是**桌面版布局**（本项目范围里没有移动端适配）：手机浏览器能打开、能用系统文件选择器上传，
但排版偏挤、批量操作不方便。这是预期现象。
